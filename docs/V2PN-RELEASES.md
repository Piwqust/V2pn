# V2pn: обновления, релизы и v2rayN

## Как V2pn обновляется у пользователей

- У V2pn своя версия (`1.0.0`, `1.0.1`…), она хранится в `v2rayN/Directory.Build.targets`. Версия v2rayN остаётся как есть: панели подписок узнают по ней формат конфига (`User-Agent: v2rayN/7.25.6`).
- Обновления берутся из релизов GitHub-репозитория `Piwqust/V2pn` (константа `V2pnInfo.Repo`). Из канала v2rayN приложение не обновляется: оттуда пришёл бы v2rayN вместо V2pn.
- Через 20 секунд после запуска и потом раз в 6 часов V2pn проверяет, есть ли новая версия.
- Если включено «Обновлять V2pn автоматически» (по умолчанию включено), пакет скачивается в фоне в `guiTemps/V2pnUpdate`. В шапке появляется «Перезапустить и обновить». Установка происходит по этой кнопке или при следующем запуске, поэтому работающее соединение обновление не обрывает.
- Пакет ставится только если его SHA-256 совпадает с файлом `.sha256` из релиза. Битый, недокачанный или подменённый пакет удаляется, приложение продолжает работать.
- Ставит пакет AmazTool: закрывает V2pn, распаковывает новые файлы и запускает V2pn снова. `guiConfigs/` (настройки, серверы, подписки) не трогается. Файлы в `bin/` (ядра) не перезаписываются.
- Ядра Xray, sing-box, mihomo и списки стран обновляются как в v2rayN: в окне «Обновления», блок «Ядра и списки».

## Как выпустить версию

Нужно один раз: репозиторий `Piwqust/V2pn` на GitHub, куда запушена ветка `v2pn`.

```powershell
tools/release.ps1 -Version 1.0.1 -Tag
git push origin HEAD v1.0.1
```

Первая команда прогоняет тесты, собирает пакеты x64 и arm64, записывает номер версии, делает коммит и тег. Из коммитов `V2pn: …` она составляет список изменений. GitHub Actions (`.github/workflows/v2pn-release.yml`) по тегу собирает те же пакеты и публикует релиз. Установленные V2pn увидят его в течение 6 часов или сразу при запуске.

Собрать пакеты без коммита и тега, например чтобы проверить сборку:

```powershell
tools/release.ps1 -Version 1.0.1
```

Пакеты появятся в `dist/release/1.0.1/`: `V2pn-windows-x64.zip`, `V2pn-windows-arm64.zip` и `.sha256` к каждому.

## Как подтянуть новый v2rayN

```powershell
tools/sync-upstream.ps1          # попробовать и посмотреть отчёт
tools/sync-upstream.ps1 -Apply   # и принять, если всё зелёное
```

Скрипт вливает свежий v2rayN в отдельную ветку `sync/v2rayN-…`, собирает V2pn и AmazTool, гоняет тесты. Ветка `v2pn` меняется, только когда всё прошло и указан `-Apply`. Отчёт пишется в `docs/upstream-sync/`. В нём список коммитов v2rayN и раздел «To port by hand»: что v2rayN поменял в окнах, которые V2pn переписал по-своему.

Почему так: окна, которые V2pn нарисовал заново, помечены в `v2rayN/v2rayN.Desktop/Views/.gitattributes` как `merge=ours`. При слиянии git оставляет версию V2pn и не смешивает две разметки в одном файле. Новые настройки v2rayN в этих окнах нужно переносить руками, отчёт показывает их diff. Если v2rayN привязал в коде новый элемент, сборка падает с понятной ошибкой («нет `cmbDnsMode`»). Это и есть подсказка, что переносить.

Коды выхода: `0` — влито или нечего вливать, `2` — конфликты, `3` — не собирается, `4` — упали тесты. При любой ошибке `v2pn` остаётся как была.

Раз в неделю то же самое делает `.github/workflows/v2pn-upstream.yml` и открывает pull request с отчётом. Если что-то сломалось, PR будет черновиком.

### Правила, чтобы слияния не ломались

- Новая логика V2pn живёт в своих файлах: `ServiceLib/V2pn/`, `v2rayN.Desktop/Common/`, `L.*.cs`.
- Если без правки файла v2rayN не обойтись, правка должна быть в пару строк, с комментарием `// V2pn:`.
- Переписали окно v2rayN целиком — добавьте его в `Views/.gitattributes`.

## Как проверить обновления руками и автоматически

```powershell
tools/update-e2e.ps1
```

Скрипт собирает две версии (1.0.0 и 1.0.1), поднимает локальную копию страницы релизов (`tools/fake_releases.py`) и управляет настоящими окнами V2pn через UI Automation:

| Сценарий | Что проверяет |
| --- | --- |
| `manual` | Автообновление выключено. Окно «Обновления» → «Скачать и установить». V2pn перезапускается новой версией, настройки и ядра на месте. |
| `auto` | Автообновление включено. Пакет скачивается сам, в шапке «Перезапустить и обновить». При следующем запуске ставится новая версия, пакет удаляется. |
| `damaged` | Хеш не совпадает. Пакет удалён, V2pn работает дальше на старой версии. |
| `rollback` | Старая версия распакована поверх новой руками. Запускается, настройки на месте. |

Скрипт ничего не публикует и не трогает V2pn, которым вы пользуетесь. Каждая копия запускается в песочнице (`tools/sandbox.ps1`): системный прокси не меняется, порт свой.

Запустить любую сборку рядом с рабочим V2pn:

```powershell
tools/sandbox.ps1 -From v2rayN/v2rayN.Desktop/bin/Release/net10.0 -Dest $env:TEMP/v2pn-try -Launch
tools/sandbox.ps1 -Dest $env:TEMP/v2pn-try -Stop
```
