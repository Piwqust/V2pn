# V2pn для провайдеров: оформление партнёра

[In English](README.md)

VPN-провайдер может оформить V2pn для людей со своей подпиской: своё имя, логотип и цвета. В этих цветах V2pn рисует два вида: «Неон», одну колонку как VPN-приложение на телефоне, и «Пропуск», обычный V2pn с картой провайдера. Подключение, серверы, настройки и состояние защиты остаются за V2pn. Человек в любой момент переключается между обычным V2pn и оформлением провайдера.

Эта страница для разработчиков провайдера: что отдавать, как это подписывается и проверяется и что покажет V2pn.

## Быстрый старт

1. Установите V2pn и включите режим разработчика: О программе → обновления → «Режим разработчика».
2. Откройте меню ☰ → «Конструктор оформления». Впишите имя и id, выберите цвета, вид, в котором откроется пакет, кнопку и окно «Неона», фон карты «Пропуска», картинки и кнопки. Справа сразу виден «Неон» (или карта «Пропуска», если пакет открывается в нём) в трёх размерах окна, светлый и тёмный. Сертификат для этого не нужен.
3. «Посмотреть в V2pn» примерит тему на само приложение. В заголовке окна будет пометка «Предпросмотр», там же её можно убрать.
4. «Сохранить пакет…»: получится папка с `partner.json` и картинками.
5. В разделе «Заявка на сертификат» нажмите «Создать ключ…» и сохраните `provider-key.pem` у себя, никому его не передавайте. Впишите домены подписки и пакета, отметьте права и нажмите «Сохранить заявку…».
6. Отправьте `request.json` владельцу V2pn. Если в пакете есть `routing.json`, `transport.json` или `core.json`, приложите их (раздел 5).
7. Владелец пришлёт `cert.json` и `cert.json.sig`. Положите их в папку пакета.
8. Подпишите пакет: «Подписать моим ключом» в конструкторе или `dotnet run tools/partner.cs -- pack <папка> --key provider-key.pem`.
9. Выложите папку по https на домене из сертификата, например `https://example.com/v2pn/`.
10. Добавьте к ответу подписки заголовок `v2pn-partner: https://example.com/v2pn/` (раздел 6).
11. Проверьте всё разом: `dotnet run tools/partner-check.cs -- https://example.com/s/<токен подписки>` (раздел 11).

Без конструктора то же самое делают `tools/partner.cs new-key`, `request` и `pack` (разделы 1 и 2).

## Что получает провайдер

| | Любая панель | Партнёр (сертификат от V2pn) |
| --- | --- | --- |
| Название подписки, трафик, срок, объявление, кнопки поддержки и кабинета (стандартные заголовки) | да | да |
| Баннеры, напоминание о продлении, подключение при запуске, порядок серверов, обновление и проверка при запуске (заголовки Happ, INCY и v2RayTun) | да | да |
| Переезд подписки на другой ваш домен (`new-url`, `new-domain`) | нет | да |
| Ссылки `v2pn://add` с сайта или из бота провайдера | да | да, и V2pn пишет, что провайдер — подтверждённый партнёр |
| Знак провайдера на его подписке в списке V2pn | нет | да |
| Оформление V2pn в цветах провайдера: «Неон», как приложение на телефоне, и «Пропуск», обычный V2pn с картой провайдера | нет | да, с правом `edition` |
| Тариф, состояние серверов по проверке провайдера, устройства, сбои в оформлении | нет | да, с правом `account` и API |
| Описание серверов (группы, страны, назначение) и до четырёх своих кнопок | нет | да, с правом `actions`, его получает каждый партнёр |
| Закрытые настройки: скрытые адреса серверов, ссылку нельзя переслать | нет | да, с правом `lock` после ручной проверки |
| Свои маршруты, фрагментация, дополнительные серверы и балансировка | нет | да, с правами `routing`, `transport`, `core` после ручной проверки каждого файла |

## Как это работает

1. Подписка провайдера отвечает с заголовком `v2pn-partner`: это адрес папки с подписанным пакетом.
2. После каждого обновления подписки V2pn скачивает из этой папки `cert.json` и `partner.json` и проверяет:
   - `cert.json` подписан корневым ключом партнёров V2pn, не истёк и не отозван;
   - `partner.json` подписан ключом, который назван в сертификате;
   - подписка и папка лежат на доменах из сертификата;
   - каждая картинка и каждый проверенный файл (`routing.json`, `transport.json`, `core.json`) совпадают по размеру и SHA-256 с `partner.json`, а проверенный файл ещё и с хэшем в сертификате.
3. Если всё сошлось, V2pn сохраняет пакет и один раз предлагает оформление: «Открыть оформление <провайдер>» или «Остаться в обычном V2pn».
4. Человек переключает оформление названием в заголовке окна, в меню трея, клавишами Ctrl+1…9 (⌘ на Mac) или на странице «Оформление». Там же он настраивает «Неон»: светлый или тёмный, акцент.

Если пакет не прошёл хотя бы одну проверку, он не используется: V2pn остаётся обычным, а в окне подписки написано, что оформление провайдера не прошло проверку. Серверы при этом работают как обычно.

## 1. Ключи и сертификат

Создайте пару ключей (ECDSA P-256), закрытую часть храните у себя. В конструкторе это «Создать ключ…», в терминале:

```
dotnet run tools/partner.cs -- new-key provider-key.pem
```

или через OpenSSL:

```
openssl ecparam -name prime256v1 -genkey -noout -out provider-key.pem
openssl ec -in provider-key.pem -pubout -outform DER | base64
```

Сертификат выписывается по заявке. Её пишет конструктор («Сохранить заявку…») или команда:

```
dotnet run tools/partner.cs -- request --id kestrel --name "Kestrel" --domains example.com,*.example.com --key provider-key.pem --grants edition,account --contact "@kestrel_admin" --out request.json
```

Файлы на проверку добавляются так: `--review routing.json` (по одному на файл). В заявке:

- id партнёра: строчные латинские буквы, цифры и дефис, 2–32 символа (`configra`);
- имя, которое увидят люди: до 40 символов, без «V2pn»;
- домены, с которых отдаются подписка и пакет (`example.com`, `*.example.com`);
- открытый ключ (base64 от DER SubjectPublicKeyInfo, как выше);
- нужные права: `edition` (оформление), `account` (API) и, если нужно, `lock` (закрытые настройки), `routing`, `transport`, `core` (свои маршруты, транспорт и конфиг ядра, раздел 5) — эти четыре после ручной проверки. `actions` (кнопки и описание серверов) получает каждый партнёр;
- SHA-256 файлов на проверку;
- как с вами связаться.

Заявка подписана вашим ключом. Так владелец V2pn видит, что закрытый ключ у вас и что заявку по дороге не меняли. Сам закрытый ключ в заявку не попадает. Отправьте `request.json` владельцу V2pn, а файлы на проверку приложите отдельно.

Владелец проверяет подпись и смотрит, кто и что просит (`partner.cs cert --from request.json`), читает файлы на проверку и выписывает сертификат. Это делается вручную: бота или сайта, который выдаёт сертификаты, нет и не будет, потому что корневой ключ V2pn не должен лежать на сервере.

V2pn до 1.0.3 включительно не принимал сертификат с правами, которых не знал: с правом `actions` оформление там не откроется, пока человек не обновит V2pn. Новые версии пропускают неизвестные права.

В ответ придут `cert.json` и `cert.json.sig` сроком на год. Положите оба файла в папку пакета как есть.

## 2. Пакет

Папка, которая отдаётся по https по адресу из заголовка `v2pn-partner`:

```
https://example.com/v2pn/
  cert.json          от владельца V2pn
  cert.json.sig
  partner.json       ваш, подписан вашим ключом
  partner.json.sig
  logo-light.png     картинки, названные в partner.json
  logo-dark.png
  mark.png
  routing.json       необязательно, после проверки (раздел 5)
  transport.json
  core.json
```

`partner.json` ([JSON-схема](partner.schema.json)):

```json
{
  "schema": 1,
  "id": "kestrel",
  "name": "Kestrel",
  "brand": {
    "accent": "#2F7BFF",
    "logo": "logo-light.png",
    "logoOnLight": "logo-dark.png",
    "mark": "mark.png"
  },
  "edition": { "variants": ["neon", "pass"], "default": "neon" },
  "theme": {
    "palette": { "brand": ["#2F7BFF", "#00C2A8"] },
    "background": { "type": "gradient", "colors": ["#1E3A8A", "#2F7BFF"] },
    "connect": "round",
    "window": "mini"
  },
  "links": { "cabinet": "https://example.com/cabinet", "support": "https://t.me/example_support" },
  "api": "https://example.com/v2pn/api/",
  "assets": [
    { "name": "logo-light.png", "size": 10913, "sha256": "f602…cf08" }
  ]
}
```

| Поле | Что с ним делает V2pn |
| --- | --- |
| `id` | должен совпадать с id партнёра в сертификате |
| `name` | показывается в заголовке, переключателе и интро; до 40 символов, без «V2pn» |
| `brand.accent` | `#RRGGBB`; акцент оформления, пока человек не выбрал другой |
| `brand.logo`, `brand.logoOnLight` | широкий логотип для тёмного и светлого фона (заголовок окна, верх «Неона», карта «Пропуска»): от 2:1 до 8:1, 32–256 px в высоту, прозрачный фон (подойдёт 340×96) |
| `brand.mark` | квадратный знак на прозрачном фоне для карточки подписки: 64–512 px (подойдёт 128×128) |
| `edition.variants` | какие из видов `neon` («Неон») и `pass` («Пропуск») предлагает пакет, в порядке списка (раздел 9). Без списка — оба: «Неон» первым, если в пакете есть `theme`, иначе «Пропуск» |
| `edition.default` | вид, который откроется первым |
| `theme` | ваша тема: цвета бренда, фон карты «Пропуска», кнопка и окно «Неона» (раздел 9) |
| `links.cabinet`, `links.support` | кнопки в оформлении, если в заголовках подписки их нет |
| `api` | базовый адрес вашего API (с правом `account`, на домене из сертификата) |
| `assets` | каждая картинка и каждый проверенный файл с размером и SHA-256; заполняет `tools/partner.cs pack` |

Картинка, которая не подходит под своё место, там не показывается (V2pn покажет имя или ничего), а `tools/partner-check.cs` скажет, какая и почему; остальной пакет работает.

Чего пакет не задаёт — нарочно: раскладку, размеры, отступы, шрифт, скругления и цвета интерфейса. Оба вида V2pn рисует сам, а все цвета светлого и тёмного варианта выводит из цветов бренда и проверяет, что текст читается (WCAG AA, 4,5:1). Благодаря этим ограничениям оформление работает при любом размере окна, в светлом и тёмном варианте, у любого провайдера.

Ограничения: `partner.json` до 64 КБ, `cert.json` до 16 КБ, не больше 8 картинок, только PNG, WebP или JPEG, до 1 МБ каждая, имена файлов без папок. Кроме картинок — только `routing.json`, `transport.json` и `core.json`, до 64 КБ каждый.

Подписывайте `partner.json` после каждого изменения: в конструкторе кнопкой «Подписать моим ключом» или командой

```
dotnet run tools/partner.cs -- pack <папка пакета> --key provider-key.pem
```

или своими средствами: ECDSA P-256 над SHA-256 точных байтов `partner.json`, подпись DER в base64 в файле `partner.json.sig`. Отдавайте файлы байт в байт, без перекодировки концов строк: V2pn проверяет те байты, которые получил. Конструктор и `partner.cs pack` пишут одни и те же байты `partner.json`.

## 3. Серверы и кнопки

С правом `actions` (его получает каждый партнёр) пакет описывает серверы подписки и задаёт до четырёх своих кнопок. Кнопка — это подпись, значок и действие из каталога V2pn: своей логики в приложении у провайдера нет. Решение о сервере принимает либо V2pn по своим замерам, либо ваш API.

### Описание серверов

```json
"servers": [
  { "name": "🇩🇪 Германия 2", "group": "Основные", "country": "DE", "city": "Берлин",
    "purpose": ["youtube"], "priority": 5, "note": "Быстрый канал до Европы" },
  { "host": "nl1.example.com", "group": "Для игр", "purpose": ["games"] },
  { "name": "Резерв", "hidden": true }
]
```

| Поле | Что делает V2pn |
| --- | --- |
| `name` или `host` | находит сервер вашей подписки: по точному имени (как в ссылке) или по адресу; хотя бы одно из двух обязательно |
| `group` | до 24 символов; заголовок в списке серверов подписки и в оформлении. Группы идут в том порядке, в каком впервые встречаются в пакете, серверы без группы — в конце, под «Другие» |
| `country` | код ISO 3166 из двух букв: флаг и место на карте вместо догадки по имени |
| `city` | до 32 символов, строкой под именем |
| `purpose` | для чего сервер: `youtube`, `games`, `mobile`, `whitelist`, `streaming`, `ai`, `torrents`. V2pn пишет это словами («YouTube», «Игры», «Мобильный интернет», «Белые списки», «Стриминг», «Нейросети», «Торренты») меткой на строке сервера. Другие значения пропускает |
| `priority` | целое от −1000 до 1000; при равных замерах выбирается сервер с большим |
| `hidden` | `true`: сервер не показывается и не предлагается. Подключиться к нему можно только по рекомендации вашего API |
| `note` | до 60 символов, строкой под именем |

Поле длиннее предела V2pn не показывает (обрезанной строки не будет), а `partner-check` скажет какое. Записей не больше 300.

### Кнопки

```json
"actions": [
  { "id": "fast",   "label": "Самый быстрый",    "icon": "bolt",   "do": "connect.best", "strategy": "ping" },
  { "id": "stable", "label": "Самый стабильный", "icon": "shield", "do": "connect.best", "strategy": "stable", "scope": { "group": "main" } },
  { "id": "yt",     "label": "Для YouTube",      "icon": "play",   "do": "connect.recommend", "purpose": "youtube" },
  { "id": "renew",  "label": "Продлить",         "icon": "card",   "do": "open.renew" }
]
```

`id` — строчные буквы, цифры, `-` и `_`, до 32 символов; `label` — до 24 символов; `icon` — один из значков V2pn: `bolt`, `shield`, `play`, `game`, `card`, `chat`, `globe`, `star`, `refresh`, `check`, `info`, `gift` (с другим кнопка будет без значка).

| `do` | Что делает V2pn |
| --- | --- |
| `connect.best` | проверяет серверы и подключает к лучшему по `strategy`: `ping` — наименьшая задержка сейчас; `stable` — больше всего ответов за последние 10 проверок V2pn, потом наименьшая медиана, потом наименьший разброс; `load` — наименьшая нагрузка из `GET servers` (без чисел нагрузки — по пингу). `scope` сужает выбор: `group`, `purpose` или список `servers` (имена или адреса) |
| `connect.recommend` | спрашивает `GET <api>recommend?purpose=<purpose>` и подключает к первому серверу из ответа, который есть в подписке и отвечает. Если API не ответил или никто из названных не отвечает — к самому быстрому серверу с этим назначением. Нужен API |
| `connect.server` | к серверу `server` (имя или адрес) |
| `connect.group` | к самому быстрому серверу группы `group` |
| `open.cabinet`, `open.renew`, `open.support` | открывает кабинет, продление или поддержку: ссылки из заголовков подписки, иначе `links` пакета |
| `open.link` | открывает `url`: https на домене из сертификата или `t.me`, либо `tg:` |
| `subscription.update` | обновляет подписку |
| `check.services` | проверяет через текущее подключение, открываются ли YouTube, Telegram и ChatGPT, и показывает результат |
| `info.card` | показывает карточку из `GET <api>card?id=<id кнопки>` в рамке с вашим именем. Нужен API |

Где кнопки: в обычном V2pn и в «Пропуске» под кнопкой подключения, пока выбран сервер вашей подписки, и в «Неоне» первыми строками списка серверов, при любой ширине окна. На экране не больше четырёх кнопок: V2pn берёт первые четыре, которые может выполнить, а неизвестное действие, кнопку без нужного поля или кнопку, которой нужен API, когда его нет, пропускает. После подключения V2pn пишет, куда подключился и почему: «Германия 2 — самый быстрый», «Нидерланды — по проверке <провайдер>». Повторное нажатие той же кнопки раньше чем через 3 секунды ничего не делает.

## 4. Закрытые настройки

С правом `lock` провайдер может закрыть настройки своей подписки, как в Happ и INCY: заголовок `hide-settings: 1` или `"lock": true` в пакете. Право выдаётся после ручной проверки: объясните, от чего вы защищаете серверы. Без права заголовки и поле ничего не делают, иначе любая подписка могла бы спрятать от человека, куда идёт его трафик.

Для серверов этой подписки V2pn тогда:

- не показывает адреса, порты и ключи (в списке, таблице, карточке подключения, поиске по адресу);
- не открывает редактор сервера, не даёт поделиться им, скопировать ссылку, показать QR-код, выгрузить конфиг или перенести сервер в другую подписку;
- не кладёт эти серверы в резервную копию (после восстановления их вернёт обновление подписки);
- не даёт менять ссылку подписки, её User-Agent, заголовки и конвертацию и держит ваши значения подключения при запуске и порядка серверов;
- пишет на карточке подписки и в её окне: «Настройки закрыл провайдер <имя>».

`hide-url: 1` (тоже только с правом `lock`) прячет и саму ссылку подписки.

Что у человека остаётся всегда: подключиться и отключиться, выбрать любой сервер подписки, удалить подписку, вернуться в обычный V2pn, свои серверы и маршруты рядом с вашими, kill switch и обновления V2pn.

Защита не абсолютная: конфиг ядра лежит на диске, и опытный человек его прочитает. Цель та же, что у Happ: чтобы адреса нельзя было переслать в два нажатия.

## 5. Проверенные файлы: маршруты, транспорт, конфиг ядра

Три файла пакета меняют то, как идёт трафик, поэтому V2pn использует их только после ручной проверки. Владелец V2pn читает файл и выписывает сертификат с правом на него: в поле `reviewed` сертификата записан SHA-256 этого файла. Поменяли файл — V2pn перестаёт его использовать, пока не придёт новый сертификат с новым хэшем, а в окне подписки пишет: «Маршруты <провайдер> изменились после проверки и не используются». Остальной пакет работает как прежде.

| Файл | Право | Что делает |
| --- | --- | --- |
| `routing.json` | `routing` | ваш режим в меню «Что идёт через VPN» |
| `transport.json` | `transport` | фрагментация и шум при подключении к вашим серверам |
| `core.json` | `core` | дополнительные серверы, цепочки, балансировка и правила к ним для ваших серверов |

Файлы лежат в папке пакета рядом с картинками и перечислены в `assets` с размером и SHA-256, как картинки (`tools/partner.cs pack` добавит их сам). Имена ровно такие, каждый файл до 64 КБ. Все три работают только с серверами вашей подписки; чужие подписки и свои серверы человека их не видят.

```json
"reviewed": {
  "routing.json": "16732e2a91e3d657874fa65783b5f98f8ff09caa505c174325eaaeb833187e74",
  "transport.json": "7fa0471883888fa10c85491b3a5fd116d72193e98ebde400f76fec3a81fa4760"
}
```

### Маршруты: routing.json

```json
{
  "name": "YouTube, Telegram и ИИ через VPN",
  "rules": [
    { "domains": ["geosite:youtube", "geosite:telegram", "domain:chatgpt.com"], "ips": ["geoip:telegram"], "to": "proxy" },
    { "domains": ["domain:gosuslugi.ru", "domain:sberbank.ru"], "to": "direct" },
    { "domains": ["geosite:category-ads-all"], "to": "block" }
  ],
  "default": "direct"
}
```

| Поле | |
| --- | --- |
| `name` | подпись режима в меню, до 40 символов (необязательно) |
| `rules` | до 50 правил по порядку, до 500 записей в правиле и 2000 всего |
| `rules[].domains` | `example.com` или `domain:example.com` (сайт и поддомены), `full:` (только этот адрес), `keyword:` (от 3 символов), `geosite:` (список из файлов геоданных) |
| `rules[].ips` | адрес, сеть (`91.108.4.0/22`) или `geoip:` |
| `rules[].to` | `proxy` — через ваш сервер, `direct` — напрямую, `block` — не открывать |
| `default` | куда идёт всё остальное: `proxy` или `direct` |

Регулярных выражений нет: проверяющий должен прочитать каждую запись. Первыми V2pn сам ставит правила «локальная сеть напрямую». `block` нельзя для широкого: `geoip:`, целая зона (`domain:ru`), сеть шире /16, локальная сеть. Списки `geosite:` и `geoip:` V2pn берёт из файлов runetfreedom, как для своих российских режимов, и скачивает их, когда человек выбирает ваш режим; тег, которого там нет, остановит ядро.

В V2pn это ещё один режим в меню «Что идёт через VPN» — «Маршруты <провайдер>», пока выбран сервер вашей подписки. V2pn один раз сообщает, что режим появился, но сам его не включает: выбирает человек. Если партнёрство закончилось (подписку удалили, сертификат истёк или отозван) или файл изменился после проверки, режим пропадает, а если он был выбран, V2pn переключается на «Всё через VPN».

### Транспорт: transport.json

```json
{
  "fragment": { "packets": "tlshello", "length": "100-200", "interval": "10-20" },
  "noise": [ { "rand": "10-20", "delay": "10-16" } ]
}
```

| Поле | |
| --- | --- |
| `fragment.packets` | `tlshello` или диапазон пакетов от 1 до 10 (`1-3`) |
| `fragment.length` | размер кусков в байтах, от 1 до 1500 |
| `fragment.interval` | пауза между кусками в миллисекундах, от 0 до 200 |
| `noise` | до 8 записей: `rand` — случайные байты (от 1 до 1024), `delay` — пауза в миллисекундах (от 0 до 200) |

- Xray: фрагментация на ваших серверах с TLS и REALITY, которые подключаются напрямую (для REALITY V2pn ставит `packets` 1-3, `tlshello` с ним не работает); шум — на серверах mKCP и Hysteria.
- sing-box: включается его фрагментация TLS, размеры кусков он выбирает сам; шума у него нет.
- Для ваших серверов это заменяет фрагментацию из настроек человека, для остальных подключений ничего не меняется.
- `mux` не принимается: у Xray и sing-box это разные протоколы, и обоим нужна поддержка на сервере.

### Конфиг ядра: core.json

```json
{
  "core": "xray",
  "outbounds": [
    { "tag": "ai-us", "protocol": "vless",
      "settings": { "vnext": [ { "address": "us.example.com", "port": 443, "users": [ { "id": "…", "encryption": "none" } ] } ] },
      "streamSettings": { "network": "raw", "security": "tls", "tlsSettings": { "serverName": "us.example.com" } } }
  ],
  "balancers": [ { "tag": "ai", "selector": ["ai-us", "proxy"], "strategy": "leastPing" } ],
  "observatory": { "probeUrl": "https://www.gstatic.com/generate_204", "probeInterval": "5m" },
  "rules": [ { "domains": ["geosite:openai", "domain:claude.ai"], "to": "ai" } ]
}
```

| Поле | |
| --- | --- |
| `core` | `xray` или `sing-box`: файл добавляется только в конфиги этого ядра |
| `outbounds` | до 8 outbound в формате ядра. Xray: `vless`, `vmess`, `trojan`, `shadowsocks`, `socks`, `http`, `hysteria`, `wireguard`; цепочка — через `streamSettings.sockopt.dialerProxy`. sing-box: те же и `hysteria2`, `tuic`, `anytls`, а также `urltest` для выбора самого быстрого; цепочка — через `detour` |
| `dialer` | тег outbound, через который подключаются все серверы вашей подписки (необязательно) |
| `balancers` | только Xray, до 4: `selector` — ваши теги или `proxy`, `strategy` — `random`, `roundRobin`, `leastPing` или `leastLoad` |
| `observatory` | только Xray: `probeUrl` (https) и `probeInterval` (от 10s до 1h) для `leastPing` и `leastLoad` |
| `rules` | до 32 правил с `domains` и `ips`, как в `routing.json`; `to` — ваш outbound, балансировщик или `proxy` |
| `allowTop` | только sing-box: `ntp`, `certificate` — что может оставить подписка, которая отдаёт целый конфиг sing-box (файлы из них V2pn всё равно убирает) |

- Ваши теги получают приставку `partner-<id>-`, поэтому не пересекаются с тегами V2pn. `proxy` — сервер вашей подписки, к которому подключился человек.
- Каждый outbound проходит фильтр подписок V2pn без изменений: никаких файлов, слушающих портов, API, `tor`, `reverse`, своего `domain_resolver`. Иначе файл не принимается.
- Правила стоят после всех правил человека (закреплённых программ, правил выбранного режима, правил, которые человек добавил в режим «Маршруты <провайдер>») и только перед правилом по умолчанию в конце режима. Поэтому сайт, который человек пускает напрямую или блокирует, так и останется, что бы ни было в ваших правилах. Они ведут только на ваши outbound и балансировщики: что идёт напрямую или блокируется, решает `routing.json`. Адреса локальной сети в них запрещены.
- Если в `outbounds` есть TLS и вы прислали `transport.json`, V2pn фрагментирует и их.
- Человек может выключить переключатель «Настройки соединения <провайдер>» в окне подписки: тогда V2pn не использует ни `transport.json`, ни `core.json`.

### Как получить проверку

1. Проверьте файлы сами: `dotnet run tools/partner.cs -- review <папка пакета>` перечислит простыми словами, что делает каждый (каждое правило, каждую настройку, каждый outbound, блокировки и всё, что касается DNS), а `tools/partner-check.cs` проверит формат и фильтр.
2. Пришлите владельцу V2pn файлы и короткое описание: что они делают и зачем.
3. Владелец читает файлы и выписывает сертификат: `partner.cs cert … --review routing.json --review transport.json --review core.json`.
4. Право действует, пока действует сертификат, то есть год, потом проверка повторяется. Любое изменение файла — новая проверка и новый сертификат.

Что смотрит проверяющий:

- маршруты не отправляют сайты банков, Госуслуг и почты на ваши серверы, если человек ждёт, что они идут напрямую;
- DNS не уходит на ваш сервер без шифрования;
- не блокируется то, что открылось бы и без VPN;
- транспорт работает с вашими серверами и не трогает чужие подключения;
- в конфиге ядра только то, что описано в заявке.

Если правила нарушены, сертификат отзывается через канал релизов, как обычно.

Совместимость: V2pn до 1.0.3 включительно не принимает сертификат с правами `routing`, `transport`, `core` и пакет, в `assets` которого есть эти файлы. Там оформление не откроется, пока человек не обновит V2pn.

## 6. Заголовки подписки

| Заголовок | |
| --- | --- |
| `v2pn-partner: https://example.com/v2pn/` | папка пакета: https, заканчивается на `/`, без query, на домене из сертификата |
| `v2pn-account-token: <токен>` | необязательный; свой у каждой подписки, до 200 символов из `A–Z a–z 0–9 - _ . ~`; уходит в ваш API как bearer-токен |
| `profile-title`, `subscription-userinfo`, `profile-update-interval`, `support-url`, `profile-web-page-url`, `announce` | стандартные; V2pn показывает их и в обычном виде, и в вашем оформлении |

Другие клиенты заголовки V2pn пропускают.

Если подписка отдаёт целиком конфиг Xray, sing-box или Clash, а не ссылки на серверы, V2pn запускает его только после фильтра. Остаются серверы, маршрутизация между ними, DNS и балансировка. Локальные порты слушают только на `127.0.0.1`. Убирается:

- API ядра, статистика и внешняя панель управления;
- журналы в файлы;
- пути к любым файлам на компьютере;
- TUN: его включает сам V2pn;
- reverse в Xray, а в sing-box — tor и tailscale.

Конфиг для других ядер V2pn из подписки не запускает. Проще всего отдавать V2pn ссылки на серверы.

### Заголовки Happ, INCY и v2RayTun

V2pn читает и те заголовки, которые провайдеры уже отдают для Happ, INCY и v2RayTun, так что панель, настроенная под них, работает в V2pn без изменений. Всё это работает для любой подписки без сертификата, кроме переезда подписки. Регистр в именах заголовков не важен. Текст можно отдавать как есть или как `base64:<UTF-8 в base64>` (кириллицу — только так). Ссылки — только `https:` и `tg:`, остальные V2pn отбрасывает.

| Заголовок | Что делает V2pn |
| --- | --- |
| `announce-url` | кнопка «Подробнее» под объявлением (`announce`) |
| `sub-info-text`, `sub-info-color`, `sub-info-button-text`, `sub-info-button-link` (Happ) | баннер под подпиской в списке, над её серверами, в окне подписки и в вашем оформлении: до 200 символов, кнопка до 25. `red`, `blue` и `green` выбирают красный, синий или зелёный из цветов V2pn, всё остальное — синий. `sub-info-text: 0` убирает баннер. |
| `banner-text`, `banner-button-text`, `banner-button-url` или `banner-url`, `premium-url` (INCY) | тот же баннер, если баннера Happ нет. Кнопка ведёт на `banner-button-url`, иначе на `banner-url`, иначе на `premium-url`. Цвета INCY (`banner-bg-color` и другие) V2pn не берёт. |
| `sub-expire`, `sub-expire-button-link` (Happ); `expiry-banner-text`, `expiry-banner-button-text`, `expiry-banner-button-url` или `expiry-banner-url` (INCY) | напоминание о продлении вместо баннера: за 3 дня до конца срока из `subscription-userinfo` и после него. Ваш текст, если вы отдаёте `expiry-banner-text`, иначе текст V2pn: «Подписка закончится через 2 дн.», «Подписка закончилась». Кнопка «Продлить» ведёт на вашу ссылку продления, иначе на `profile-web-page-url`, иначе кнопки нет. V2pn показывает напоминание и без `sub-expire`; `sub-expire: 0` его выключает. |
| `subscription-autoconnect: 1`, `subscription-autoconnect-type: lastused`, `lowestdelay` или `random` | подключение, когда V2pn запускается выключенным: к последнему серверу этой подписки, к самому быстрому (V2pn сначала проверяет серверы и берёт самый быстрый из ответивших) или к случайному. Работает, если выбранный сервер из этой подписки или сервер не выбран и подписка первая в списке. V2pn, который оставили подключённым, подключается как раньше, а сервер, добавленный человеком вручную, остаётся его выбором. Человек может выключить это для подписки. |
| `subscriptions-sort-type: ping`, `alphabet` или `without` (Happ); `sort-order: ping`, `name` или `none` (INCY) | порядок серверов этой подписки: быстрые сверху, по имени или как вы их отдаёте. Человек может выбрать другой. |
| `subscription-ping-onopen-enabled: 1` | проверка серверов этой подписки при запуске V2pn |
| `update-always: true` (v2RayTun), `subscription-auto-update-open-enable: 1` (Happ) | обновление этой подписки при запуске V2pn. Только этой: Happ обновляет все. |
| `new-url`, `new-domain` | переезд подписки на новый адрес. Только для партнёра V2pn, в сертификате которого есть новый домен, и только в HTTP-заголовках ответа с серверами. Только https; `new-url` важнее `new-domain`, и при ошибке в `new-url` V2pn не переходит к `new-domain`; `new-domain` сохраняет порт, путь и параметры; переезд на тот же домен или на адрес другой подписки V2pn пропускает. Без сертификата заголовки не действуют: иначе подписку мог бы увести любой, кто отвечает по старому адресу. В журнале человек видит, куда переехала подписка. |
| `ping-type`, `check-url-via-proxy` | V2pn их читает и хранит, но пока не применяет: он проверяет каждый сервер через сам сервер по адресу проверки, который выбрал человек |
| `hide-settings`, `hide-url` | закрытые настройки подписки, только для партнёра с правом `lock` (раздел 4); без права V2pn их только хранит |

**В теле подписки.** Как Happ и INCY, V2pn читает строки `#ключ: значение` в начале подписки, которая отдаёт список ссылок, обычным текстом или в base64:

```
#profile-title: base64:S2VzdHJlbCBWUE4=
#sub-info-text: base64:0KHQutC40LTQutCwIDMwJSDQvdCwINCz0L7QtCDQtNC+INC/0Y/RgtC90LjRhtGL
#subscription-autoconnect: 1
vless://…
```

Заголовок важнее той же строки в теле. Только из заголовков: `new-url`, `new-domain`, баннеры INCY и заголовки V2pn. В полном конфиге Xray, sing-box или Clash таких строк V2pn не ищет.

**Что V2pn не берёт.** `routing`, фрагментацию, шум, fronting и другие настройки, которые меняют трафик: им нужна ручная проверка V2pn, они появятся отдельными правами. Цветовые профили, `change-user-agent` и остальные настройки чужих приложений V2pn пропускает.

**User-Agent V2pn.** V2pn скачивает подписку с User-Agent `v2rayN/7.25.6 V2pn/1.0.3`: сначала агент v2rayN, потому что по нему панели выбирают формат, а V2pn читает те же форматы, потом имя и версия V2pn. Если человек задал подписке свой User-Agent, уходит он.

**Правило ответа в Remnawave.** Правила проверяются сверху вниз до первого совпадения, поэтому ставьте это правило выше правил для `v2rayN`. Если вы не партнёр V2pn, уберите `v2pn-partner`. `v2pn-account-token` у каждого человека свой, его отдаёт панель, а не правило.

```json
{
  "name": "V2pn",
  "description": "Баннеры и настройки для V2pn",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    { "headerName": "user-agent", "operator": "CONTAINS", "value": "v2pn", "caseSensitive": false }
  ],
  "responseType": "XRAY_BASE64",
  "responseModifications": {
    "applyHeadersToEnd": true,
    "headers": [
      { "key": "v2pn-partner", "value": "https://example.com/v2pn/" },
      { "key": "announce-url", "value": "https://example.com/news" },
      { "key": "sub-info-text", "value": "base64:0KHQutC40LTQutCwIDMwJSDQvdCwINCz0L7QtCDQtNC+INC/0Y/RgtC90LjRhtGL" },
      { "key": "sub-info-color", "value": "green" },
      { "key": "sub-info-button-text", "value": "base64:0JrRg9C/0LjRgtGM" },
      { "key": "sub-info-button-link", "value": "https://t.me/example_bot" },
      { "key": "sub-expire", "value": "1" },
```

## 7. Ссылки

`v2pn://add?url=<ссылка на подписку, в URL-кодировке>&name=<имя>` открывает V2pn, и он спрашивает, добавить ли подписку. V2pn принимает и ссылки Happ (`happ://add/<ссылка>`), v2RayTun (`v2raytun://import/<ссылка>`) и Hiddify (`hiddify://import/<ссылка>`). Если такая подписка уже есть, V2pn просто говорит об этом. В Windows схему `v2pn` регистрирует установленное приложение, на macOS — пакет приложения.

## 8. API (необязательно)

С правом `account` и адресом `api` на домене из сертификата V2pn спрашивает:

`GET <api>account` с заголовком `Authorization: Bearer <v2pn-account-token>`, когда открывается оформление, и дальше раз в 30 минут, пока оно на экране:

```json
{
  "plan": "Личный",
  "status": "ACTIVE",
  "servers": { "healthy": 11, "total": 14 },
  "devices": { "count": 2, "limit": 5 },
  "until": "2027-01-31",
  "note": "В воскресенье ночью плановые работы."
}
```

`GET <api>status` без токена, раз в 15 минут:

```json
{ "incidents": [ { "title": "Германия не отвечает", "text": "Уже чиним.", "severity": "major" } ] }
```

Для кнопок и описания серверов (право `actions`) V2pn спрашивает ещё, всегда с токеном подписки, если он есть:

`GET <api>servers` — так же часто, как `account`: при открытии оформления или когда выбран сервер вашей подписки, и не чаще раза в 30 минут. Те же поля, что в `servers` пакета, плюс `load` (0–100) и `healthy`. Значения API важнее значений пакета, поле за полем:

```json
{ "servers": [ { "name": "🇩🇪 Германия 2", "load": 31, "healthy": true }, { "host": "nl1.example.com", "load": 90, "healthy": false } ] }
```

`GET <api>recommend?purpose=youtube` — при нажатии кнопки `connect.recommend`: серверы по порядку, лучший первым (имена или адреса, до 50):

```json
{ "servers": ["🇳🇱 Нидерланды", "🇩🇪 Германия 2"] }
```

`GET <api>card?id=plan` — при нажатии кнопки `info.card` с этим `id`: заголовок до 60 символов и простой текст до 600, переносы строк сохраняются, разметки нет:

```json
{ "title": "Тариф «Семья»", "text": "5 устройств, без ограничения трафика.\nОплачено до 31 января 2027." }
```

Все поля необязательны: V2pn берёт то, что знает, остальное пропускает. Ответ — JSON до 64 КБ с кодом 200, всё остальное считается отсутствием ответа. С токеном V2pn не идёт по редиректам. Если ваш сайт там, где человек, заблокирован, V2pn повторит запрос через VPN. `servers.healthy`/`total` заменяют в оформлении счёт по пингу V2pn («11 из 14 по проверке <провайдер>»). Отдавайте только числа, без адресов серверов и учётных данных.

## 9. Оформление: «Неон» и «Пропуск»

V2pn рисует для каждого партнёра два вида в его цветах:

| Вид | Что это |
| --- | --- |
| `neon` («Неон») | одна колонка, как VPN-приложение на телефоне. Сверху имя или логотип провайдера и переключатель Proxy/VPN. Дальше кнопка подключения, под ней плашка состояния и маршрут («Что идёт через VPN»), ваши кнопки и ссылки на кабинет и поддержку. Внизу карточка с подпиской (тариф, устройства, срок, полоса трафика, баннер) над списком серверов |
| `pass` («Пропуск») | обычный V2pn (боковая панель, карта мира, стеклянная панель подключения, карточка состояния) с вашей картой над карточкой состояния, как банковская карта в Wallet: логотип, тариф, устройства и срок, сколько дней осталось крупными цифрами, полоса трафика, ссылки «Продлить» и «Кабинет», текст баннера меткой |

Какие виды предлагает пакет, задаёт `edition.variants`, а какой из них откроется первым — `edition.default`. Дальше человек выбирает сам на странице «Оформление».

Configra получает те же два вида, что и все. Старые названия видов V2pn читает: `signature` и `warm` открываются как `pass`, а `theme`, `cabinet`, `studio` и `ascii` — как `neon`. Название, которого V2pn не знает, он пропускает.

### Тема

Тема — это поле `theme` в `partner.json` (пример в разделе 2). Оба вида берут из неё цвета, «Пропуск» — ещё фон своей карты, «Неон» — кнопку подключения и окно. Раскладку, шрифт (Geist) и скругления V2pn выбирает сам. Проще всего собирать тему в конструкторе (быстрый старт выше): он пишет это поле сам и сразу показывает результат.

| Поле | Варианты | По умолчанию |
| --- | --- | --- |
| `palette.brand` | 1–3 цвета `#RRGGBB`. Первый — акцент: кнопка подключения, свечение «Неона» и карта «Пропуска», когда фон `solid`. Остальные красят кольцо вокруг кнопки «Неона» | `brand.accent` |
| `background` | фирменная область карты «Пропуска»: `{"type": "solid"}` — первый цвет бренда; `{"type": "gradient", "colors": [от 2 до 4 цветов]}` — градиент из угла в угол; `{"type": "image", "art": "<картинка пакета>"}` | `solid` |
| `connect` | кнопка «Неона»: `round` — большая круглая кнопка в светящемся кольце цветов бренда; `toggle` — строка с флагом, сервером и переключателем | `round` |
| `window` | окно «Неона»: `mini` — в первый раз «Неон» откроется в мини-окне 380×640, дальше окно остаётся таким, каким его оставил человек; `full` — окно не меняется | `mini` |

Мини-окно 380×640 — основная форма «Неона». В окне шире карточка с подпиской встаёт рядом с колонкой. «Неон» сначала тёмный; на странице «Оформление» человек переключает светлый и тёмный вариант и может заменить ваш акцент одним из цветов V2pn. Пока открыт «Неон», окна и меню V2pn тоже берут его цвета. В «Пропуске» действуют настройки вида обычного V2pn, а ваша карта стоит поверх них.

Места для картинок:

| Место | Размер |
| --- | --- |
| `brand.logo` | логотип для тёмного фона: от 2:1 до 8:1, 32–256 px в высоту, прозрачный фон |
| `brand.logoOnLight` | тот же логотип для светлого фона, те же размеры |
| `brand.mark` | квадратный знак на прозрачном фоне для карточки подписки: 64–512 px |
| `theme.background.art` | картинка карты «Пропуска»: 640–3200 px по каждой стороне, не шире 3:1 |

Цвета. Вы задаёте 1–3 цвета бренда, остальные цвета светлого и тёмного варианта V2pn выводит сам:
- текст читается везде по WCAG AA: 4,5:1 для текста, 3:1 для кнопок и полей;
- где цвет бренда становится текстом или фоном под текстом, V2pn делает его темнее или светлее ровно настолько, чтобы читалось;
- цвет, похожий на зелёный «защищено», жёлтый «внимание» или красный «не защищено», V2pn сдвигает от него;
- на картинку карты V2pn кладёт затемнение такой силы, чтобы текст читался при любой картинке.

Если поле темы задано неправильно (цвет не в формате, неизвестное значение `connect` или `window`, картинка не подходит под место), V2pn берёт для этого поля значение по умолчанию, а тема продолжает работать. Прежние `connect` `capsule` и `bar` становятся `round`. Поля тем с шаблонами (`template`, `font`, `corners`, `density`, `blocks`, `art`, `palette.tone`) V2pn читает без ошибки, но не использует, а конструктор при сохранении убирает их из пакета. `tools/partner.cs pack`, `tools/partner-check.cs` и конструктор перечисляют, что заменено или пропущено и почему. Неизвестные поля V2pn пропускает.

Примеры тем лежат в `tools/demo/themes/`: aurora («Неон», круглая кнопка, мини-окно, карта с градиентом), ember (открывается в «Пропуске», карта с картинкой `dunes.jpg`, окно `full`), pine («Неон», переключатель, мини-окно, карта цвета бренда). `tools/edition-matrix.ps1 -Theme <папка>` снимает «Пропуск» и «Неон» с каждой кнопкой подключения (`-Connects round,toggle`) на трёх размерах окна, «Неон» в светлом и тёмном варианте.

Что пакет поменять не может: раскладку обоих видов и шрифт, цвета и плашку состояния (зелёное «защищено», красное «не защищено»), смысл кнопки подключения (выбрать между круглой кнопкой и переключателем — может), знак V2pn и пометку «на V2pn», переключатель обратно в обычный V2pn, настройки и маршрутизацию. Свои маршруты провайдера — только отдельный режим, который человек выбирает сам (раздел 5).

## 10. Жизнь партнёрства

- **Обновления.** Меняйте и переподписывайте пакет когда угодно: V2pn заберёт его при следующем обновлении подписки.
- **Срок.** Сертификат действует год. V2pn проверяет его при запуске и каждый час; когда срок выходит, оформление закрывается с пояснением и открывается обычный V2pn. Просите новый за месяц, `tools/partner-check.cs` предупредит.
- **Уход.** Перестаньте отдавать `v2pn-partner`, и оформление пропадёт при следующем обновлении. Если человек удалит вашу подписку, вместе с ней уйдёт и оформление.
- **Отзыв.** Владелец V2pn может отозвать сертификат до срока; установленные приложения узнают об этом из канала релизов и закроют оформление.

## 11. Проверка

```
dotnet run tools/partner-check.cs -- https://example.com/s/<токен настоящей подписки>
dotnet run tools/partner-check.cs -- --folder ./v2pn --subscription https://example.com/s/<токен>
```

Скрипт выполняет проверки самого V2pn с ключами, встроенными в приложение, и на каждом шаге пишет OK или что не так: заголовки, сертификат, подписи, домены, картинки, тему (что взято, что заменено и почему, какие старые поля пропущены, как V2pn поправил цвета), описание серверов и кнопки (что V2pn пропустит и почему), закрытые настройки, проверенные файлы (формат, фильтр, совпадает ли хэш с сертификатом), API, включая `servers`, `recommend` и `card` для ваших кнопок.

Пример пакета с описанием серверов, кнопками и тремя проверяемыми файлами и локальный сервер с подпиской, пакетом и API для предпросмотра лежат в `tools/demo/partner/` и `tools/demo/demo_partner.py`, примеры тем — в `tools/demo/themes/`.

Чтобы увидеть тему до публикации и без сертификата, откройте папку пакета в конструкторе и нажмите «Посмотреть в V2pn». Предпросмотр помечен в заголовке окна, не подписан, остаётся только на этом компьютере и пропадает после перезапуска.

Чтобы проверить весь путь с подпиской, попросите у владельца V2pn сертификат для предпросмотра на `127.0.0.1`, отдавайте пакет и тестовую подписку со своего компьютера по http и включите в V2pn режим разработчика (О программе → обновления). Тогда V2pn примет пакет с `127.0.0.1`.

## Приватность

V2pn не отправляет вашим серверам ничего сверх того, что отправил бы любой подписке: пакет и API запрашиваются так же, как сама подписка, с user agent V2pn, а для `account` ещё с токеном, который выдали вы. Трафик человека, его другие подписки, устройство и всё, что V2pn измеряет, никуда не отправляются.
