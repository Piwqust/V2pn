## Resolution

Resolved in `V2pn: v2rayN 8.0.1 (91c61b1f)`:

- `ResUI.resx`: the two sides differed only in the last line; v2rayN's five update-check messages are in, and
  `ResUI.ru.resx` got Russian for them (separate commit).
- `UpdateService.cs`: V2pn's second try of the rule lists the other way under the blocking bypass (the `failed`
  flag) stays inside v2rayN's new error handler, which appends the inner exception to the message.
- `ThemeSettingViewModel.cs`: V2pn's `FontFamily` with the bundled Inter as fallback stays (v2rayN made the same
  string-to-FontFamily fix, without the fallback).
- `ThemeSettingView.axaml.cs`: V2pn's translated theme names stay; the language list takes v2rayN's compiled
  bindings in the axaml (the code-behind bindings and their `using` go).

What may behave differently:

- Core update checks (Xray, mihomo, sing-box): the latest tag is found by `GitHubReleaseSource` - the release
  redirect as before, or the GitHub API for pre-releases and locked versions, now with a fallback to the git tags
  of the repository when the API fails. The check view shows a line per stage ("Checking Xray updates via ...").
- Downloads: a failed file no longer counts as finished (it fires `Error` once, inner exception in the text);
  among several rule-list files the first failure cancels the rest, and V2pn's other-way retry then takes all of
  them again.
- Xray `raw` + HTTP header: the request template (Host, path) reaches the config again; since v2rayN's AOT change
  Xray used its built-in request.
- An XDRIVE server under sing-box is refused at connect with "core does not support network" instead of starting
  without a transport.
- `guiNConfig.json` lists its sections in a new (alphabetical) order; the content is the same.
- The WPF project is `v2rayN/v2rayN.Windows` now; V2pn does not build it.

Build: Desktop and AmazTool Release, 0 errors. Tests: 898; one full run green, one with `ChecksNeverOverlap`
(V2pnNetworkWatchTests) failed - a timing test that fails 2 of 3 full runs on unchanged `v2pn` as well and passes
alone.

Smoke test (Debug, sandbox off screen, 40 fake servers): the link added the subscription (40 servers), Connect
started xray from the sandbox folder, "Server not responding" as expected. Every window of the debug rows opened
and drew correctly. The log has only the core update checks timing out through the dead fake server and a
"DialogHost is already open" from opening two dialogs back to back by automation.

## Ported

- Server form (`a545a6f4`, `4e00b6d8`): V2pn's form offers XDRIVE since 1.4.0. When the core chosen in the form
  (or the protocol's core from Settings) cannot carry the transport - sing-box with XDRIVE, kcp or xhttp - a note
  under the transport card says so, and Save is refused with v2rayN's own message. The rules are probed from
  v2rayN's `NodeValidator` (`ServiceLib/V2pn/V2pnServerChecks.cs`), so later additions there apply too.

Skipped: v2rayN's `MainWindow.axaml.cs` change (its vertical tab strip shows Servers/Information instead of
hiding) belongs to v2rayN's own window layout, which V2pn replaced.
